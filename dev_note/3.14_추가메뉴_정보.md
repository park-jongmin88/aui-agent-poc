# MLflow 3.14 추가 메뉴 정보

MLflow 3.14 GenAI 에 새로 생긴 두 메뉴(Playground, Review)를 우리 프로젝트 관점에서 정리한다.

> 그림: `3.14_추가메뉴_정보.png` (생성 스크립트: `make_314_diagram.py`)

<br>

## 한눈에

```
[우리 코드 (터미널)]      [공유 데이터]       [3.14 UI 기능 (클릭)]
 client.py         →    Gateway 엔드포인트  ←    Playground
 evaluate.py       →    Trace (대화기록)   ←    Review
```

- **둘은 별개로 동작** — 우리 코드는 터미널 실행, 3.14 기능은 MLflow UI 클릭
- **같은 데이터를 공유** — Playground 는 우리가 등록한 gateway 를, Review 는 우리가 쌓은 trace 를 사용

<br>

## 1. Playground — 프롬프트 실험장 (UI)

브라우저에서 프롬프트를 바로 실험하는 기능.

- 우리가 이미 쓰는 **MLflow AI Gateway 엔드포인트 + Prompt Registry 버전**에 그대로 연결됨
- experiment 에서 열어 모델 엔드포인트를 고르고, system/user/assistant 멀티턴 대화 구성
- temperature, max tokens, top-p, penalty, stop sequence 조정, 도구 정의, JSON 스키마 출력 제한 가능

**vs 우리 client.py**
- Playground = 프롬프트만 빠르게 실험 (UI, 파이프라인 없음)
- client.py = 전체 파이프라인(prompt+rag+tool+llm) 테스트
- 둘 다 같은 gateway 엔드포인트를 본다

<br>

## 2. Review — 사람이 직접 평가 (UI)

사람이 trace 를 검토하고 구조화된 피드백을 남기는 기능.

- Pass/Fail, 범주형, 숫자, 자유 텍스트 질문 세트로 리뷰 큐를 만들어 리뷰어 그룹에 배정
- 큐 상태가 공유되어, 한 명이 끝내면 그룹 전체에 처리 완료로 표시(중복 방지)
- 답변은 각각 trace 에 바로 기록됨 (피드백=평가, 기대값=정답)
- 결과가 평가·judge 정렬·데이터셋 구축에 바로 쓰임. `mlflow.genai.review_queues` SDK 로 스크립트화 가능

**vs 우리 judge (evaluate.py)**
- Review = 사람이 평가 (수동, 정확) — **gateway 인증이 필요 없다**
- judge = LLM 이 평가 (자동/수동)
- **핵심**: 지금 judge 자동 평가가 gateway 인증으로 막혀 있는데, Review 는 사람이 하므로 인증 문제가 없다 → **자동 평가 대안이 될 수 있음**

<br>

## 우리 상황과의 관계

| 항목 | 우리 코드 | 3.14 UI 기능 | 관계 |
|------|-----------|--------------|------|
| 대화/프롬프트 테스트 | client.py | Playground | 같은 gateway 공유, 용도 다름 |
| 답변 평가 | judge (evaluate.py) | Review | judge=LLM, Review=사람 |

<br>

## 버전 주의

- 이 두 메뉴는 **3.14.0 신규**. 우리는 현재 **3.13** 이라 아직 없음 → 쓰려면 3.14 업그레이드 필요.
- 3.14 에서 **litellm/gepa 가 genai extras 에서 제거**됨. 우리는 judge 용으로 litellm 을 쓰므로, 3.14 로 올릴 경우 `requirements.txt` 에 litellm 을 명시적으로 유지해야 함 (현재 `litellm==1.83.0` 명시돼 있어 문제 없음).
- 특히 **Review** 는 judge 자동 평가가 막힌 지금 상황의 대안으로 검토 가치가 있음.
