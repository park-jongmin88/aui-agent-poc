# Key / 보안 관리 - 계획

<br>

## 목적

사용자와 관리자의 권한을 분리해 Key/토큰 및 외부 서비스 연계를 관리한다.

<br>

## 화면 구조

```
[사용자 화면]
  - Key 값 관리
  - 외부 서비스 연계 상태 관리

[관리자 화면]
  - 전체 키/토큰 수집
  - 정책 관리
  - 권한 관리
  - 보안 관리
  - 감사(Audit) 관리
```

<br>

## ⚠ 보안 요건

개인정보를 포함하는 시스템에 상응하는 보안 요건 준수가 필요해 보임.
→ 신중한 설계 필요, 착수 전 보안 요구사항 확정 필수.

<br>

## 하고 싶은 것 (착수 시)

- 사용자 Key 관리(등록/조회/삭제)부터 최소 범위로 시작
- 관리자 기능(정책/권한/보안/감사)은 조직 보안 정책 확인 후 착수
